LEARN IT

Conditions and flowcharts

A condition is a question that can only be answered True or False (Yes or No): “Is the mark 50 or more?” is a condition; “What is the mark?” is not. A flowchart draws the steps of an algorithm with arrows:
  • Oval: where you START or STOP.   Rectangle: an action (input, calculate, display).
  • Diamond: a decision, with one arrow in and two arrows out, labelled Yes and No.
A decision placed inside the Yes or No path of another decision is nested. Nesting lets you ask a second question only when the first answer needs it.

LEARN IT

AND, OR and NOT

Programmers join conditions with three words:
  • A AND B is True only when both A and B are True.
  • A OR B is True when at least one of them is True.
  • NOT A flips the answer: NOT True is False, NOT False is True.
A truth table lists every possible combination of True and False and shows the result. With two conditions there are 2 × 2 = 4 rows.

LEARN IT

IF…THEN…ELSE

An IF statement chooses between two paths. If the condition is True the statement after then runs; if it is False the statement after else runs. Never both. Two traps: (1) There is no semicolon before else: a semicolon ends the whole IF, so the else has nothing to belong to and Delphi reports an error. (2) A branch with more than one statement must be wrapped in begin … end; otherwise only the first statement belongs to the IF.
Delphi
if iMark >= 50 then
begin                               // two statements: begin ... end
  lblResult.Caption := 'Pass';
  btnCertificate.Enabled := True;
end                                 // NO semicolon before else
else
  lblResult.Caption := 'Not yet';   // one statement: no begin needed
LEARN IT

Nested IF and the ELSE IF chain

Put an IF inside the else (or the then) of another IF to ask a second question. Delphi tests from the top and takes the first True; after that it skips the rest. So the order matters: test the most demanding condition first.
Delphi
// a chain: the order of the tests matters
if iMark >= 80 then
  sResult := 'Distinction'
else
  if iMark >= 50 then
    sResult := 'Pass'
  else
    sResult := 'Not yet';

// a second question is only asked when the first is True
if bRegistered then
begin
  if rFine = 0 then
    sMsg := 'You may borrow'
  else
    sMsg := 'Pay your fine first';
end
else
  sMsg := 'Please register';

Brackets, and the order of AND, OR and NOT

Delphi applies NOT first, then AND, and OR last. It does this even if you wrote the OR first, just like multiplication happens before addition in maths. Comparisons such as iAge >= 14 are applied after AND/OR, so every comparison needs its own brackets; otherwise Delphi tries to AND the numbers together and gives an error. Always use brackets: they make the meaning clear to you and to the computer.
Delphi
// WRONG, does not compile:  if iAge >= 14 and iAge <= 19 then
if (iAge >= 14) and (iAge <= 19) then
  ShowMessage('Teenager');

if (bPaid) or (bSRC) then
  ShowMessage('Entry allowed');

if not (iMark >= 50) then      // same as iMark < 50
  ShowMessage('Not yet');

bResult := bA or bB and bC;    // means bA or (bB and bC)
bResult := (bA or bB) and bC;  // a different question!
LEARN IT

The IN operator

IN checks whether a value is in a set, written in square brackets. It replaces long chains of OR. A set can list values, give a range with .., or mix both. It works with whole numbers and characters (not with real numbers or strings).
Delphi
if cLetter in ['A', 'E', 'I', 'O', 'U'] then
  ShowMessage('Vowel');

if iMonth in [6..8] then          // June to August
  ShowMessage('Winter');

if not (iSeat in [1..15, 40..55]) then
  ShowMessage('Seat must be 1-15 or 40-55');

LEARN IT

The CASE statement

CASE looks at one value (the selector) and jumps to the line that matches. A line holds one value, several values separated by commas, or a range written with two dots. The optional else catches everything else.
  • The selector must be a whole number or a character: not a real number, not a string.
  • Ranges must not overlap: a value may not appear in two lines.
  • CASE has no begin, but it finishes with end.
Delphi
case iZone of
  1    : iFare := 12;
  2, 3 : iFare := 18;
  4..6 : iFare := 25;
else
  iFare := 40;
end;

MessageDlg: ask the user a question

ShowMessage only tells the user something. MessageDlg asks and gives you the answer. It is a function with four parts: the text, the icon (mtConfirmation, mtInformation, mtWarning, mtError), the buttons (mbYesNo, mbOKCancel, mbYesNoCancel) and a 0 for help (always 0 for now). It returns which button was clicked: mrYes, mrNo, mrOK or mrCancel. Compare the answer in an IF.
Delphi
if MessageDlg('Delete all the entries?', mtConfirmation, mbYesNo, 0) = mrYes then
  memOut.Clear
else
  ShowMessage('Nothing was deleted');

LEARN IT

Four string tools

Length(s) counts the characters (spaces included) and returns a whole number. UpperCase(s) turns a whole string into capitals. UpCase(c) does the same for one character. Trim(s) removes spaces at the start and end of a string. Each one returns a new value: the original does not change unless you store the result back in a variable. Position numbers start at 1, so s[1] is the first character.
Delphi
sName := Trim(edtName.Text);        // '  aya ' becomes 'aya'
iLen := Length(sName);              // 3
sBig := UpperCase(sName);           // 'AYA'
cFirst := UpCase(sName[1]);         // 'A'  (one Char, so UpCase)
sName := UpperCase(Trim(edtName.Text));   // functions can be nested

Validate before you process

Garbage in, garbage out. A program must check data before it uses it. Common checks: presence (text is not empty), range (a number is within limits) and length (the right number of characters). FormCreate and Activate: when does code run?

Windows creates your form once and then you can click away and back. Two events let you run code at the right moment. FormCreate happens once, when the form is first created, before it appears: use it for set-up like Randomize, clearing labels and disabling buttons. FormActivate happens every time the form becomes the active window (for example when you return to it): use it to refresh something or to put the cursor in an edit box.
Delphi
procedure TForm1.FormCreate(Sender: TObject);
begin
  Randomize;                    // once only
  lblResult.Caption := '';
  btnCalc.Enabled := False;
end;

procedure TForm1.FormActivate(Sender: TObject);
begin
  edtName.SetFocus;             // every time the form is activated
end;

Inside the system unit

Think of the system unit as a school. The motherboard is the school building and its corridors: the main circuit board that every part plugs into. The CPU is the teacher: it carries out the instructions of every program (speed in GHz). RAM is the desks: temporary working space for the programs and files in use right now, and it is emptied when the power goes off. Storage (hard disk or SSD) is the library: the files are kept there permanently, even when the computer is off. Ports are the doors where cables and devices connect.

LEARN IT

Why network, and how big is the network?

A network is two or more devices linked so that they can share. People network computers to share printers, files and one internet connection, to communicate (email, messaging) and to keep data and backups in one place. Networks are named by size: PAN (Personal Area Network): around one person, a few metres, such as Bluetooth earbuds. HAN (Home Area Network): inside one home, such as the Wi-Fi router joining phones, TV and laptop. LAN (Local Area Network): one building or campus, such as a school computer lab. WAN (Wide Area Network): towns, countries, continents, such as the Internet or a bank's network of branches and ATMs.

LEARN IT

Client-server and peer-to-peer

In a client-server network one powerful computer, the server, controls the network: it holds the files, manages log-ins and security, runs the printer and does the backups. The other computers are clients. It is expensive and the administrator has control, but if the server fails everybody is affected. In a peer-to-peer (P2P) network every computer has equal status: any can share files or a printer, and there is no central computer. It is cheap and simple, but security and backups are handled on each computer, so it suits only a few devices.
