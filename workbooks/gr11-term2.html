LEARN IT

Why files? And two names for one file

A variable lives in RAM, which is wiped when the program closes or the power goes off in load shedding. A text file lives on the disk, so the data is still there tomorrow. It holds plain characters in lines, just like Notepad. Even a number in a text file is only text, so convert it with StrToInt before you calculate with it.

Picture your school locker. The number painted on the locker door is its real address: the physical file name, such as Sales.txt on the disk. The key tag in your bag is how you talk about it: the logical file name, a variable of type TextFile. AssignFile attaches the tag to the locker, so it must come first.
Delphi
var
  tFile : TextFile;                  // logical name: a variable in the program
begin
  AssignFile(tFile, 'Sales.txt');    // link it to the physical name on the disk
  // from here on the commands use tFile, never the physical name
LEARN IT

The file commands

Every file job follows the same pattern: link, open, work, close.
CommandWhat it does
AssignFile(tFile, 'Data.txt')Links the logical name to the physical name. Always first.
Reset(tFile)Opens an existing file for reading, at line 1.
Rewrite(tFile)Creates a new, empty file for writing. If the file exists, everything in it is erased.
Append(tFile)Opens an existing file for writing at the end. Old lines are kept.
ReadLn(tFile, sLine)Reads one line into sLine and moves on to the next line.
WriteLn(tFile, sText)Writes sText to the file as one new line.
EOF(tFile)True when there is nothing left to read.
CloseFile(tFile)Saves and closes the file. Never forget it.
FileExists('Data.txt')True if that file is on the disk. Takes the physical name.
In this course every file job is written from first principles with these commands. There is no one-line shortcut for reading or saving a whole file.
LEARN IT

Reading, writing and appending

while not EOF(tFile) means “keep going while there is still something left to read”. Each ReadLn takes one line and moves the position on, so the loop reaches the end by itself. To save data use Rewrite for a fresh file, or Append to add to the end of an existing one. The very first time a program runs there is no file yet, and Append would fail, so it asks FileExists first.
Delphi
// READ every line
AssignFile(tFile, 'Names.txt');
Reset(tFile);
while not EOF(tFile) do
begin
  ReadLn(tFile, sLine);        // one line per pass
  memOut.Lines.Add(sLine);
end;
CloseFile(tFile);

// ADD a line, or create the file the first time
AssignFile(tFile, 'Sales.txt');
if FileExists('Sales.txt') then
  Append(tFile)
else
  Rewrite(tFile);
WriteLn(tFile, edtItem.Text + ',' + edtPrice.Text);
CloseFile(tFile);
LEARN IT

When the file is missing

Reset on a file that does not exist makes the program crash. There are two ways to be safe. FileExists asks before opening. try..except runs the risky code in the try part; if an error happens, Delphi jumps straight to the except part, skips the rest of the try part, and the program carries on. File errors are of the type EInOutError. Many programmers use both.
Delphi
// Method 1: ask first
if FileExists('Names.txt') then
  ...
else
  ShowMessage('Names.txt was not found');

// Method 2: try..except
AssignFile(tFile, 'Names.txt');
try
  Reset(tFile);                 // error here if the file is missing
  ...                           // read the lines
  CloseFile(tFile);
except
  on E: EInOutError do
    ShowMessage('Could not read Names.txt');
end;

LEARN IT

From a line of text to parallel arrays

Each line of the file is one record and the commas separate its fields. We keep each field in its own array. The arrays are parallel: position 3 of every array belongs to the same item. We do not know how many lines the file has, so the arrays are declared with a constant MAX and a counter iCount remembers how many places were really filled.
Pos(',', s) gives the position of the first comma. Copy(s, start, length) takes a piece. Delete(s, start, length) cuts a piece away, so after taking a field we delete it and its comma.
Delphi
const
  MAX = 50;
var
  arrItem  : array[1..MAX] of String;
  arrPrice : array[1..MAX] of Integer;
  arrQty   : array[1..MAX] of Integer;
  iCount   : Integer;                  // how many items were really read

// ----- in the event handler
iCount := 0;
AssignFile(tFile, 'Stock.txt');
Reset(tFile);
while (not EOF(tFile)) and (iCount < MAX) do
begin
  ReadLn(tFile, sLine);                // e.g. 'Sugar,32,10'
  Inc(iCount);                         // the next free place
  iPos := Pos(',', sLine);
  arrItem[iCount] := Copy(sLine, 1, iPos - 1);
  Delete(sLine, 1, iPos);              // '32,10' is left
  iPos := Pos(',', sLine);
  arrPrice[iCount] := StrToInt(Copy(sLine, 1, iPos - 1));
  Delete(sLine, 1, iPos);              // '10' is left
  arrQty[iCount] := StrToInt(sLine);
end;
CloseFile(tFile);
LEARN IT

Using the arrays, then writing a report

After reading, every loop runs from 1 to iCount, never to MAX. The usual patterns work as before: a running total, a counter, and highest so far where we remember the index of the winner, because that same index also gives the winner's other fields. A report has three parts: a heading written once, a body written inside a loop, and a summary written once. Use Rewrite so that each report starts fresh.
Delphi
AssignFile(tOut, 'Report.txt');
Rewrite(tOut);
WriteLn(tOut, 'TUCK SHOP STOCK');              // heading: once
for i := 1 to iCount do                        // body: repeats
  WriteLn(tOut, arrItem[i] + ': R' + IntToStr(arrPrice[i]));
WriteLn(tOut, 'Items: ' + IntToStr(iCount));   // summary: once
CloseFile(tOut);

LEARN IT

Procedures: write once, call by name

A procedure does a job but does not hand an answer back. Write it once, give it a name, and call it by writing its name as a statement. This avoids repeating code, makes the program easier to read and means a mistake is fixed in one place only. In a form, a procedure is declared in the private section of the class and written in the implementation section with TForm1. in front of its name, just like an event handler.
Delphi
type
  TForm1 = class(TForm)
    ...
  private
    procedure ShowBanner;                    // declaration
  ...
implementation
procedure TForm1.ShowBanner;               // definition
begin
  memOut.Lines.Add('*****************');
  memOut.Lines.Add('  KASI TUCK SHOP');
  memOut.Lines.Add('*****************');
end;

procedure TForm1.btnStartClick(Sender: TObject);
begin
  ShowBanner;                              // call
  memOut.Lines.Add('Open 7:00 to 16:00');
  ShowBanner;                              // call again
end;
LEARN IT

Value parameters

A parameter is a placeholder in the procedure's header that receives information. An argument is the actual value you give when you call. The number, order and types of the arguments must match the parameters. A value parameter receives a copy: the procedure may change its copy, but the caller's variable stays as it was.
Delphi
procedure TForm1.ShowLine(sItem: String; iPrice: Integer);   // 2 parameters
begin
  memOut.Lines.Add(sItem + ': R' + IntToStr(iPrice));
end;

// calls: the values in the brackets are the arguments
ShowLine('Bread', 18);
ShowLine(arrItem[3], arrPrice[3]);        // arguments can be expressions
LEARN IT

Local and global variables

A variable declared inside a procedure (and the procedure's own parameters) is local: it exists only while that procedure runs and no other code can see it. A variable declared at the top of the unit, below Form1: TForm1, is global: every procedure can read and change it and it keeps its value while the program runs. Prefer local variables and parameters; use global variables only for values that really are shared, such as the arrays and iCount that hold the data from a file. Set a global variable to a value yourself before you use it. (Think of a reminder in your own diary, which only you can read, and a notice on the staffroom board, which everybody can read and change.)
Delphi
var
  Form1  : TForm1;
  iTotal : Integer;                // global: all procedures can use it

procedure TForm1.AddToTotal(iAmount: Integer);
var
  iDouble : Integer;               // local: only exists in here
begin
  iDouble := iAmount * 2;
  iTotal := iTotal + iDouble;      // changes the global
end;

LEARN IT

Functions: a job that returns a value

A function is written like a procedure but its header ends with a colon and the return type. The answer is stored in the special variable Result. A function has no meaning on its own: the call must be used, so assign it, display it or test it. A procedure call, by contrast, is a statement on its own. A function may have no parameters (then write no brackets) or several. To choose between the two kinds of method ask: do I need an answer back? If yes, write a function; if the method only has to do something, such as display, clear or write to a file, write a procedure. A function that calculates should not also display: let the caller decide what to do with the answer.
Delphi
function TForm1.CalcVat(rPrice: Real): Real;      // one parameter, returns a Real
begin
  Result := rPrice * 0.15;
end;

function TForm1.RollDie: Integer;                  // no parameters
begin
  Result := Random(6) + 1;
end;

// using them
rVat := CalcVat(200);                              // 30
lblVat.Caption := FloatToStrF(CalcVat(StrToFloat(edtPrice.Text)), ffFixed, 8, 2);

LEARN IT

Validation with a Boolean function

Validation checks that data is acceptable (a sensible range, the right length, the right type of characters) before the program uses it. A function that returns Boolean is perfect: it answers True (valid) or False (not valid) and can be used straight in an if or a repeat..until. Validation checks only that the data is reasonable, not that it is true.
Delphi
function TForm1.IsValidMark(iMark: Integer): Boolean;
begin
  Result := (iMark >= 0) and (iMark <= 100);       // range check
end;

function TForm1.IsValidCell(sCell: String): Boolean;
var
  i : Integer;
begin
  Result := (Length(sCell) = 10) and (Copy(sCell, 1, 1) = '0');   // length and format
  for i := 1 to Length(sCell) do
    if not (sCell[i] in ['0'..'9']) then                           // type check
      Result := False;
end;

// keep asking until the answer is valid
repeat
  sCell := InputBox('Cell number', 'Enter 10 digits starting with 0:', '');
until IsValidCell(sCell);

Shaping, throttling and protocols

A protocol is a set of rules that devices follow so that they understand each other. Internet service providers (ISPs) also manage how fast your connection is. Shaping means the ISP gives some types of traffic priority over others, for example video calls over large downloads, to keep the network running smoothly. Throttling means the ISP deliberately slows your connection, for example after you have used up the fast data in your package.

Passwords, encryption and multi-layer verification

A strong password is long (at least 12 characters), mixes upper case, lower case, digits and symbols, is not based on your name or birth year, and is different for every account, so that one leak does not open everything. Encryption scrambles data (plaintext) into unreadable ciphertext using a method and a secret key. Only someone with the right key can turn it back. It protects data that is stored (an encrypted phone) and data on the move (HTTPS and WhatsApp). Multi-layer (multi-factor) verification asks for more than one proof of who you are, taken from different groups: something you know (a password or PIN), something you have (your phone, which receives a one-time PIN) or something you are (a fingerprint or face). A thief who steals only the password still cannot get in.
LEARN IT

Blockchain, digitalisation and the gig economy

A blockchain is a digital ledger (record book) kept as a chain of blocks. Each block holds a group of records and the fingerprint of the block before it, so the blocks are linked. Copies are kept on many computers, with no single owner, so nobody can quietly change one block: it would no longer match the next one, and the other copies would disagree. Its purpose is to record transactions in a way that is open, shared and very hard to cheat. Cryptocurrencies such as Bitcoin use it, and so do systems that track goods from farm to shop.

Digitalisation means moving tasks from paper and people to digital systems. It brings speed, accuracy and new jobs, but some routine jobs disappear and people without devices or data are left behind. The gig economy is work made up of short jobs (“gigs”) arranged through online platforms, such as e-hailing drivers, food couriers and freelancers. Workers choose their hours and can earn extra money, but have no job security, no paid leave or pension and an unpredictable income.

LEARN IT

Database and DBMS

A database is an organised collection of related data, stored in tables so that it can be found, changed and shared quickly. In a table each row is a record (everything about one learner or product) and each column is a field (one kind of information). The primary key is the field that is different for every record and so identifies it, such as LearnerNo.

A DBMS (database management system) is the software that creates a database and manages it. Its functions are to: store and organise the data; let users retrieve it by searching, sorting and filtering (querying); add, change and delete records while validating them; control who may do what (security); make backups and recover after a crash; let many users work at once; and produce reports. Examples are Microsoft Access, MySQL, Microsoft SQL Server, Oracle and PostgreSQL. Delphi is not a DBMS: a Delphi program connects to one.
LEARN IT

Types of database and database careers

A desktop (personal) database is stored on one computer and used by one person or a few, such as an Access database for a small shop. A server (centralised) database is stored on a central server and many users reach it over a network, such as a school's admin system used by the teachers and the office. A distributed database is spread over several computers or servers in different places that work together and keep one another up to date, such as a bank's records or a national learner database used in every province.

A database administrator (DBA) looks after the database: security, backups, user access and keeping it fast. A database programmer (developer) writes the queries and code that let applications use the data. A database analyst studies what the organisation needs and designs the tables and how they are linked.
