Why files? And two names for one file

A variable lives in RAM. When the program closes, or the power goes off during load shedding, RAM is wiped and every value is gone. A text file is stored on the disk (hard drive, SSD or flash drive), so the data stays there until someone deletes it. A text file holds plain characters in lines, just like Notepad. Even a number in a text file is stored as text, so you must convert it with StrToInt before you calculate with it.

Think of a contact on your phone. The real phone number is the physical name. The name you tap, such as “Mom”, is a nickname that points to it. A file works the same way. The physical file name is the real name on the disk (for example Sales.txt). The logical file name is a variable of type TextFile that your program uses as a nickname. AssignFile links the two, and it must always come first.
Delphi
var
  tFile : TextFile;                  // logical name (a variable)
begin
  AssignFile(tFile, 'Sales.txt');    // link it to the physical name on the disk
  // from now on we only use tFile in the commands
LEARN IT

The file commands

Every file job follows the same pattern: link, open, work, close.
CommandWhat it does
AssignFile(tFile, 'Data.txt')Links the logical name to the physical name. Always first.
Reset(tFile)Opens an existing file for reading, starting at the first line.
Rewrite(tFile)Creates a new empty file for writing. If the file exists, everything in it is erased.
Append(tFile)Opens an existing file for writing at the end. Old lines are kept.
ReadLn(tFile, sLine)Reads one whole line into sLine and moves to the next line.
WriteLn(tFile, sText)Writes sText to the file as one new line.
EOF(tFile)End Of File: True when there is nothing left to read.
CloseFile(tFile)Saves the data and closes the file. Never forget it.

Reading a file, line by line

while not EOF(tFile) means “keep going while there is still something left to read”. Each ReadLn takes one line and moves on, so the loop reaches the end by itself. Reset crashes the program if the file does not exist, so first ask FileExists.
Delphi
// declared: tFile : TextFile;  sLine : String;
if FileExists('Names.txt') then
begin
  AssignFile(tFile, 'Names.txt');
  Reset(tFile);                   // open for reading
  while not EOF(tFile) do
  begin
    ReadLn(tFile, sLine);         // one line per pass
    memOut.Lines.Add(sLine);
  end;
  CloseFile(tFile);               // always close
end
else
  ShowMessage('Names.txt was not found');

Writing and adding to a file

Rewrite starts a new file (and wipes an old one). Append adds to the end of a file that already exists. The first time a program runs there is no file yet, so a common plan is to ask FileExists and choose Append or Rewrite.
Delphi
AssignFile(tFile, 'Sales.txt');
if FileExists('Sales.txt') then
  Append(tFile)                  // keep the old sales
else
  Rewrite(tFile);                // first sale ever: create the file
WriteLn(tFile, edtAmount.Text);  // one new line

LEARN IT

Online storage, synchronisation and collaboration

Online storage (cloud storage) means saving your files on a company's servers instead of only on your own device, and reaching them through the internet with a username and password. Google Drive, OneDrive and Dropbox are examples. You can open your files on any device, and the files survive if your phone is lost or broken, so it works like a backup. The disadvantages are that you need internet (data costs, and the router goes off during load shedding), the free space can run out, and you must trust a company with your private files.

Synchronising means that the copies of a file on your devices and in the cloud are kept identical. A change on one device goes to the cloud when the device is online, and the cloud passes it on to your other devices. If you edit offline, the change waits on that device until the connection returns. Syncing saves copying by hand, but it needs internet and uses data.

Online collaboration means several people work on the same file at the same time from different places. They see each other's changes, leave comments and use the version history to undo mistakes. The owner gives each person a permission: view, comment or edit. It removes the confusion of many copies, but it needs a good connection and careful sharing so that private files do not reach the wrong people.
LEARN IT

Online shopping and social media

Online shopping lets you compare prices, buy at any hour and have goods delivered, which helps people in small towns far from big shops. The risks are fake shops, phishing emails that pretend to be your bank, stolen card details and goods that are not as advertised. Safe shoppers use known websites that show https and a padlock, pay with a method that has extra protection such as a card with a one-time PIN, read reviews, check the return policy and ignore deals that are too good to be true.

Social media lets you stay in touch, share news and find communities. The risks are cyberbullying, strangers who are not who they say they are, fake news, spending too much time scrolling, and your digital footprint: what you post can be copied and can stay online for years. Keep your profile private, think before you post, never share your ID number or address, and tell an adult if something worries you. The law called POPIA protects personal information, and it is one more reason not to give your details to anyone who does not need them.

LEARN IT

Conversion toolbox

Binary → decimal: write the place values 128, 64, 32, 16, 8, 4, 2, 1 above the bits and add the values where the bit is 1. Example: 01101001 = 64 + 32 + 8 + 1 = 105.
Decimal → binary: divide by 2 again and again, write down each remainder, then read the remainders from the bottom up. Example: 53 gives remainders 1, 0, 1, 0, 1, 1, so 53 = 110101 (00110101 in 8 bits).
Hex → decimal: multiply the left digit by 16 and add the right digit (A = 10, B = 11 … F = 15). Example: 7C = 7 × 16 + 12 = 124.
Decimal → hex: divide by 16 and read the remainders from the bottom up. Example: 175 = 10 × 16 + 15 = AF.
Binary ↔ hex: one hex digit is exactly four bits. Example: 1011 0110 = B6.
ASCII gives every character a number: A = 65, a = 97 (32 more), 0 = 48. Unicode has room for thousands of characters, such as isiZulu letters and emoji, which ASCII cannot hold.
LEARN IT

Storage units and the revision map

1 byte = 8 bits · 1 KB = 1 024 bytes · 1 MB = 1 024 KB · 1 GB = 1 024 MB · 1 TB = 1 024 GB. To change to a smaller unit multiply by 1 024; to change to a bigger unit divide by 1 024.
TopicRemember
HardwareInput (keyboard, mouse, scanner, microphone), output (monitor, printer, speakers, projector), processing (CPU), memory (RAM, temporary), storage (HDD, SSD, flash drive), communication (NIC, router, modem).
NetworksPAN (about arm's reach), HAN (one home), LAN (one building, such as a school lab), WAN (cities and countries; the internet). Client-server has a central server; peer-to-peer has equal computers.
SecurityVirus (needs a file to be opened), worm (spreads by itself), trojan (pretends to be useful), ransomware (locks files for payment), spyware (spies), phishing (fake messages). Antivirus removes malware; firewall filters network traffic; UPS survives power cuts.

Read, count, answer

1. Read the whole question and underline the command word. 2. Count the marks: in most theory questions each mark is one separate, correct point, so [2] means two points and [4] means four. 3. Answer only what is asked: no essay for one mark, and no one-word answer for four marks. 4. Check that you have given as many points as there are marks.
LEARN IT

Plan your code, show your working

Before you write code, plan it: list the inputs, the process and the outputs, then write the steps in plain English, then the Delphi. Name your variables and write comments so a marker can follow your thinking. In traces and calculations, show your working: a marker can give marks for a correct method even if the final answer is wrong, but a bare wrong answer earns nothing. In a paper of 60 marks in 90 minutes you have about 1.5 minutes per mark, so a 6-mark question should take about 9 minutes. Leave 5 to 10 minutes to check at the end.

COMING UP NEXT TERM · warm-up

A row of school lockers

Next term you will store many values at once. Think about a corridor of 30 numbered lockers, one for each learner in a class. Each locker holds one thing: that learner's mark. You never have to give a locker its own name; you simply say “locker 17”.

(a) Suppose you had to remember 30 marks, but the only tool you had was a separate, differently named box for each mark (Mark1, Mark2, Mark3, …). How would you feel about writing out all 30 names? What about 300?
(b) How would a numbered row of lockers make it quick to add up all 30 marks, or to find the highest one?
(c) What happens if someone asks for locker 31?
