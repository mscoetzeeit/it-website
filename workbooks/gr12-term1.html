LEARN IT

A query is a question

SQL (Structured Query Language) is the language we use to talk to a database, and a query is one question. Every part of the question has its own keyword, and the parts always come in the same order.
KeywordMeansCompulsory?
SELECTwhich fields (columns) to showyes
FROMwhich table to useyes
WHEREkeep only the rows that pass a testno
ORDER BYsort the rows (ASC = small to big, the default; DESC = big to small)no
A query ends with a semicolon. SQL does not care about capital letters, but we write the keywords in capitals so they stand out. Field names and table names must be spelled exactly as in the database.
SQL
SELECT Surname, Mark
FROM tblLearner
WHERE Grade = 12
ORDER BY Mark DESC;
LEARN IT

How the database reads your query

You write SELECT first, but the database works in a different order: it takes the table (FROM), throws away the rows that fail the test (WHERE), keeps only the columns you named (SELECT) and finally sorts what is left (ORDER BY). That is the order you would follow with a pencil and the paper table. Conditions in WHERE use =, <> (not equal), <, >, <= and >=. Text goes in double quotes and numbers do not. Use SELECT * to show every field. To sort by two fields, separate them with a comma: ORDER BY Grade, Surname sorts by grade and, inside each grade, by surname.
SQL
SELECT *
FROM tblLearner
WHERE Sport = "Hockey";

SELECT Surname, Grade
FROM tblLearner
ORDER BY Grade DESC, Surname;
LEARN IT

DISTINCT: each value once

The Sport column holds Netball three times. SELECT Sport FROM tblLearner would show it three times, because there is one row per learner. Put the word DISTINCT straight after SELECT to remove repeated rows from the result.
SQL
SELECT DISTINCT Sport
FROM tblLearner
ORDER BY Sport;

LEARN IT

AND, OR, NOT and brackets

AND: both tests must be true. OR: at least one test must be true. NOT reverses a test. SQL works out AND before OR, just as maths works out × before +. So a mixed condition that you read as “(A or B) and C” must be written with brackets, otherwise it means “A, or (B and C)”. When in doubt, add brackets.
SQL
SELECT Surname
FROM tblLearner
WHERE (Sport = "Netball" OR Sport = "Hockey") AND Grade = 12;

LEARN IT

Calculated fields and aliases

In the SELECT list you can write a calculation (with +, -, *, /) instead of a field name. The database works it out for every row. Give the new column a name with AS: that name is called an alias. Without an alias the column gets a meaningless name such as Expr1001. You can also join pieces of text with &. An alias exists only in the result, so you may not use it inside WHERE: repeat the calculation instead.
SQL
SELECT ProdName, Price * Stock AS StockValue
FROM tblProduct
ORDER BY StockValue DESC;

SELECT Surname & ", " & Name AS FullName
FROM tblLearner;
LEARN IT

Aggregate functions and TOP

An aggregate function boils many rows down to one value.
FunctionGivesExample
SUM(field)the totalSUM(Stock)
MIN(field)the smallest valueMIN(Price)
MAX(field)the biggest valueMAX(Price)
AVG(field)the averageAVG(Mark)
COUNT(*)the number of rowsCOUNT(*)
WHERE is worked out first, so the aggregate only looks at the rows that passed. A query with an aggregate may not also list an ordinary field (that needs GROUP BY, in the next unit). TOP n keeps only the first n rows. It is only meaningful with ORDER BY, because “first” depends on the sort order.
SQL
SELECT COUNT(*) AS NumDear
FROM tblProduct
WHERE Price > 20;

SELECT MIN(Price) AS Cheapest, MAX(Price) AS Dearest
FROM tblProduct;

SELECT TOP 3 ProdName, Price
FROM tblProduct
ORDER BY Price DESC;

LEARN IT

GROUP BY and HAVING

GROUP BY field puts the rows that have the same value in that field into one group, and the query gives one result row per group. Every field in the SELECT list must either appear in GROUP BY or be inside an aggregate function (COUNT, SUM, AVG, MIN, MAX). HAVING filters the groups after they have been made, so it is the place to test an aggregate. WHERE filters single rows before the groups are made, and can never contain an aggregate. Inside HAVING repeat the aggregate; do not use an alias. Access lists the groups in order of the GROUP BY field.
Order of workClauseWhat it does
1FROMtake the table
2WHEREthrow away single rows
3GROUP BYmake the groups
4HAVINGthrow away whole groups
5SELECTwork out the columns and aggregates
6ORDER BYsort the result
SQL
SELECT Sport, COUNT(*) AS Num, ROUND(AVG(Mark), 1) AS AvgMark
FROM tblLearner
WHERE Grade >= 11
GROUP BY Sport
HAVING COUNT(*) >= 2
ORDER BY Sport;

LEARN IT

Joining two tables with WHERE

The tables are linked by a primary key and a foreign key: ProductID is the primary key of tblProduct and a foreign key in tblSale. To see fields of both tables in one result, list both tables after FROM, separated by a comma, and write the link as a condition in WHERE: foreign key = primary key. Further conditions follow with AND. If a field name exists in both tables, put the table name in front (tblSale.ProductID), otherwise the query is ambiguous and fails. A short table alias written after the table name saves typing: FROM tblSale S, tblProduct P lets you write S.Qty and P.Price.
SQL
SELECT tblSale.SaleID, tblProduct.ProdName, tblSale.Qty
FROM tblSale, tblProduct
WHERE tblSale.ProductID = tblProduct.ProductID
AND tblProduct.Category = "Load shedding";

SELECT S.SaleID, P.ProdName, S.Qty * P.Price AS Amount
FROM tblSale S, tblProduct P
WHERE S.ProductID = P.ProductID;

If you list two tables and forget the link, the database pairs every row of one table with every row of the other. Here are a coach table and a team table:

LEARN IT

INSERT, UPDATE and DELETE

These three statements change the table and give no rows back. To see the effect you must run a SELECT afterwards. INSERT INTO names the table, lists the fields in brackets and then gives the VALUES in the same order. An AutoNumber key is left out because the database fills it in. UPDATE changes the fields named after SET, on the rows chosen by WHERE. DELETE FROM removes the rows chosen by WHERE. Always write WHERE on UPDATE and DELETE: without it every row is changed or removed.
SQL
INSERT INTO tblProduct (ProdName, Category, Price, Stock)
VALUES ("Paraffin 1L", "Load shedding", 21.50, 15);

UPDATE tblProduct
SET Price = Price + 2
WHERE Category = "Staples";

UPDATE tblProduct
SET Price = 20, Stock = 5
WHERE ProductID = 2;

DELETE FROM tblProduct
WHERE Stock = 0;

TADOQuery: Close, SQL, Open

In Delphi, SQL is sent to the database by a TADOQuery component (we call it qryLearner). The steps are always the same: Close the query, put the SQL text in its SQL property, then run it. A long query is easier to read if you Clear the SQL and Add it line by line. Each Add is a separate line, so you do not need spaces between them (when you join pieces with + you do).
Delphi
qryLearner.Close;
qryLearner.SQL.Text := 'SELECT Surname, Mark FROM tblLearner WHERE Grade = 12 ORDER BY Mark DESC';
qryLearner.Open;

LEARN IT

The three anomalies

When the same fact is stored in many rows, three errors appear:
AnomalyWhat goes wrongIn Think First
Insertionyou cannot record one fact without recording another unrelated facta new product has no order yet
Deletiondeleting a row also destroys a fact that you wanted to keepcancelling order 1004 erases Ms Peters and the Eggs
Modification (update)one fact is changed in some rows but not in others, so the data contradicts itselfa new cell number is typed in 3 of Mrs Dube's 4 rows
The cure is to store every fact once, in its own table, and to link the tables with keys.
LEARN IT

Referential integrity and a good database

A foreign key holds the primary key of a row in another table. Referential integrity is the rule that every foreign key value must match an existing primary key value. A row whose foreign key matches nothing is an orphan. The database enforces the rule by refusing to save an orphan (a sale of ProductID 12 when no product 12 exists), and by refusing to delete a parent row (a product) that still has child rows (sales) pointing at it.
A good database has…which means
data integritydata that is accurate, consistent and complete (referential integrity and validation protect it)
minimal redundancyeach fact stored once; a planned backup is not harmful redundancy
data securityaccess only for authorised users, with different rights for different users
data independencea change to the structure does not break the programs that use it
ease of maintenanceit is easy to add, change and delete data without anomalies

Normal formThe table must…If not, then…
1NFhave one value per cell, no repeating groups of columns, and a primary keysplit the lists into separate rows; choose a key (it may need two fields)
2NFbe in 1NF and every non-key field must depend on the whole key (this only matters when the key has two or more fields)move each field that depends on only part of the key into a new table, with that part as its key
3NFbe in 2NF and no non-key field may depend on another non-key fieldmove the dependent fields into a new table whose key is the non-key field they depend on (which stays behind as a foreign key)

LEARN IT

Database, data warehouse and data mining

A database holds the current data of one system and is used for day-to-day transactions: rows are added, changed and deleted all day. A data warehouse collects historical data from many databases into one central store. Data is cleaned and put in one format before it is loaded, and it is then mostly read, for reports and analysis, not changed. Data mining is the search through such a large store for hidden patterns that nobody asked about, for example that customers who buy nappies on a Friday evening also buy snacks. The process is: extract the relevant data (with SQL), look for patterns, and turn them into knowledge that someone can act on, such as moving the snacks next to the nappies.
LEARN IT

Caring for data

An organisation's data is one of its most valuable assets, so it must be accurate (a wrong mark prints on a report: garbage in, garbage out), safe and available. Validation is the program checking that typed data is reasonable (a mark from 0 to 100). Verification checks that data matches its source (typing it twice, or proofreading against the form): validation cannot notice that 98 was typed as 89, verification can. Data integrity means the data stays correct and consistent (referential integrity, record locking). Access control gives each user a password and only the rights needed, and a log records who changed what and when. Copies kept in a second place (backups, parallel data sets) protect against loss.
LEARN IT

How to write a theory answer

Write sentences with reasons, not bullets. A marker may stop crediting a list after its first few items, so valid points lower down can be lost, but a paragraph is read in full. A list also hides whether you understand the idea, while a sentence with because or so proves it. A good paragraph has three parts: a point (what), a reason (why or how) and an example or result. Count the marks first: [4] means four separate points, so write at least four.
Weak: “cookies – tracking – adverts”. Strong: “A cookie is a small file that a website saves on your device. It records which pages you visit, so the site can remember you and show adverts for things you looked at.”
LEARN IT

Mobile hardware, performance and privacy

A smartphone has the same parts as a computer in miniature. Its CPU, graphics chip, memory and modem sit on a single chip, a System on a Chip (SoC), to save space and power. Battery life is the main limit: the faster the processor and the brighter the screen, the faster the battery drains, and a hot phone slows itself down to cool off because it has no fan. Storage is flash memory with no moving parts, and the touchscreen is small. A phone also carries sensors (GPS, camera, microphone, accelerometer) and always-on connections (Wi-Fi, 4G or 5G, Bluetooth, NFC). That makes it a very rich source of data about its owner: where they go, whom they contact and what they search. Personal risks: an app with too many permissions can track location or read contacts, data can be sold, and a lost phone exposes everything on it. Business risks: staff who use a phone for work put customer data on a device the company does not control, so a lost phone can breach privacy law; companies protect themselves with passcodes, encryption and the ability to wipe the phone remotely.
LEARN IT

Big Data and society

Big Data is data so large, fast-moving and varied that ordinary tools cannot cope. Mining it can help society: hospitals predict illness, banks detect fraud, and farmers use sensor data to decide when to irrigate. It can also harm: people lose privacy when their habits are tracked, profiles can be used to discriminate (an insurer refusing cover because of your shopping), breaches expose millions of records, and people without access to technology fall further behind. A full answer weighs both sides and says who benefits and who is affected.
