Words you must know

A database is an organised collection of data. It is stored in one or more tables, and each table holds data about one kind of thing (learners, items for sale, taxis). Every row is a record: everything about one thing. Every column is a field: one piece of information, with a name and a type.

LEARN IT

The primary key

A primary key (PK) is a field whose value is different in every record, so it picks out exactly one record. A good key is unique, never empty and never changes. Names make poor keys because two learners can share a name, so we add an ID field, often an AutoNumber. Sometimes two fields together form the key (for example StudentNo plus SubjectCode); that is a composite key.

One-to-many and the foreign key

Instead of repeating a teacher on every slip, put classes in their own table and store only the class code in each learner's record. That code is a foreign key (FK): a field that holds the primary key of another table and so links the two. One class has many learners, so this is a one-to-many (1:M) relationship. The foreign key always lives in the table on the MANY side.

LEARN IT

One-to-one and many-to-many

In a one-to-one (1:1) link each record matches exactly one record in the other table (learner and locker). It is uncommon, and the foreign key can go in either table. A many-to-many (M:M) link, such as learners and subjects, cannot be stored with a single foreign key. The fix is a linking table that holds one foreign key for each side. Every M:M becomes two 1:M links.
LEARN IT

Drawing an ERD, and referential integrity

An entity relationship diagram (ERD) shows the tables and how they are linked. Draw one box per table with the table name on top and the fields below, marking each PK and FK. Join the boxes with a line from the key field to the foreign key field, with 1 at the one end and M at the many end. Steps: (1) list the tables; (2) decide each relationship; (3) replace every M:M with a linking table; (4) put each FK on the many side; (5) draw.
Referential integrity means every foreign key value must match a primary key value that really exists in the parent table. A learner whose ClassID is 11Z when there is no class 11Z is an orphan record. The database enforces the rule by refusing to save an orphan, and by refusing (or cascading) the deletion of a class that still has learners.

How a check digit works

Our scheme: give the four digits the weights 1, 2, 3, 4, multiply, add, and take the remainder after dividing by 10 (MOD 10). That remainder is the check digit, written as the fifth digit. To check a code, recalculate from the first four digits and compare with the fifth.
Digit4195
Weight1234
Digit × weight422720
Total = 4 + 2 + 27 + 20 = 53. 53 MOD 10 = 3, so the full code is 41953. Swap two digits: 4 9 1 5 gives 4 + 18 + 3 + 20 = 45, MOD 10 = 5, which no longer matches the 3, so the error is caught. Real bank cards and South African ID numbers use a cleverer cousin of this idea, the Luhn method.
LEARN IT

When data goes wrong: mistakes and crime

Human error is a mistake by a person: typing 4 120 instead of 1 420, swapping digits, misreading handwriting, deleting the wrong file, or forgetting to update a record. Computer error comes from the machine or the program: a power failure (such as load shedding) in the middle of saving, a failing disk, a bug in a formula, or a corrupted file. Either way the data is wrong or missing and so are the decisions based on it. Validation, backups and a UPS reduce the risk.
Identity theft: a criminal uses stolen personal details (ID number, bank details) to open accounts or borrow money in someone else's name; the victim may be refused credit and spend months clearing their name. Ransomware locks or encrypts an organisation's files and demands payment to release them; the business or hospital cannot work, and without a recent backup the data may be lost for good. SQL injection is an attack on a program that sends what the user types straight to its database: the attacker types cleverly written text into a form so that the database obeys it, and can read, change or delete records. Programmers defend against it by validating every input and never mixing user text into database commands. In South Africa the POPIA law requires organisations to protect personal information.
LEARN IT

How to answer a theory question

Write theory answers in sentences, not bullet points. Here is why: in a marking guideline a list of bullets is credited only up to the number of points asked for (the first few bullets), so a long list wastes your time. A marker must read a whole paragraph, and a good one earns a mark for each separate, well-explained point. Use the shape point → explain → effect or example: “Ransomware locks the clinic's files so the nurses cannot see patient records, which delays treatment.”

Walking through the records

The table keeps a pointer to the current record. if iCount > 0 then

LEARN IT

Insert, Edit, Delete and Post

A table is normally in browse state: you may look but not touch. Insert switches to insert state (a blank new record) and Edit to edit state (the current record may change). Neither saves anything. Think of the change as a note on a sticky note: Post copies it into the table and returns to browse, and if you forget Post the change is lost. Cancel throws the change away. Delete removes the current record at once and cannot be undone, so ask the user first.

Searching and changing with loops

To find a record, loop through the table and test each one. Use a Boolean flag so you know afterwards whether it was found; the flag also lets the loop stop early (a Break inside the loop does the same). To change every record that matches, put the Edit and Post pair inside the if, and keep Next outside the if so that the loop always moves on.
Delphi
bFound := False;
dmTuck.tblItems.First;
while (not dmTuck.tblItems.Eof) and (not bFound) do
begin
  if UpperCase(dmTuck.tblItems['ItemName']) = UpperCase(edtFind.Text) then
    bFound := True
  else
    dmTuck.tblItems.Next;
end;
if bFound then
  lblPrice.Caption := FloatToStrF(dmTuck.tblItems['Price'], ffFixed, 8, 2)
else

LEARN IT

Deleting matching records: do not skip

After Delete, the record that came after the deleted one slides into the current position, so the pointer is already on an unchecked record. If you also call Next you jump over it. Move on only when you did not delete. (A shortcut for showing a subset of records is the table's Filter and Filtered properties, for example Filter := 'Category = ''Drinks''', but loops give you full control.)
Delphi
dmTuck.tblItems.First;
while not dmTuck.tblItems.Eof do
begin
  if dmTuck.tblItems['InStock'] < 10 then
    dmTuck.tblItems.Delete   // no semicolon: the else belongs to this if
  else
    dmTuck.tblItems.Next;
end;
